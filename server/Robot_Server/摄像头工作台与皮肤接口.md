# 网页 W2026.10.15-06 · 目标偏差、视线角度与三路图像

已接进实际 Flask 项目：恒星 3D 登录页、3D 与动作训练页、人员相机页，以及参数设置中的独立皮肤切换。旧原色和红黑皮肤都保留；原历史交付不改。

## 从哪里开始验收

1. 启动新版网页，打开 `http://127.0.0.1:5000/login`。用原来的访问口令登录。错误口令不会进入控制台。星空资源都在本地；WebGL 不可用时登录仍可用。
2. “设备测试 → 参数设置 → 页面外观”选择原色或 NEXUS 红黑，点击应用。选择记在当前浏览器，切换后仍在当前页。明暗偏好分别保留。
3. “3D 与动作训练”直接运行已有完整三舵机模型与动作训练，复用同源登录。录制/裁剪/保存/回放保持；实际下发仍需核对轴号与限位并明确点击。原来的“3D 姿态”保留。
4. “人员 → ①手动上传”选一张 JPEG / PNG。上传后自动使用项目原来的 YuNet + SFace CPU 引擎检测人脸，无需配置图片模型或 API Key。未登记的人脸也应画框，标“未知人员”；没有检测到人脸会明确提示。图片最大 4 MiB，最多 1600 万像素，会转为最长边 1280 的 JPEG 并移除 EXIF/GPS 元信息。
5. 在“本地人脸库”填写姓名，选 1~10 张清晰单人参考照登记，也可把当前检测照片作为参考照。然后对当前记录点击“重新检测 / 识别”，匹配成功显示姓名。检测到框和识别出姓名是两个步骤；登记照片必须只有一张足够大的脸。最多登记 50 人、每人 10 张参考照，可删除人员；默认相似度阈值 0.50、候选差值 0.08。测试的“同照登记再检测”只验证接线流程，日常准确率需用不同光照、角度的本人照片与陌生人照片验收。
6. 本机测试定时采集：选择“浏览器摄像头”，启用定时拍照，设间隔并保存，再点击打开电脑摄像头。浏览器相机需 HTTPS 或 localhost；普通局域网 HTTP 可以上传图片，但浏览器可能禁止打开相机。
7. 设置时段、暂停/恢复，检查允许/暂缓原因；时段按北京时间，不随服务器系统时区改变。例 `22:00-06:00` 支持跨午夜，留空为全天。新采集按“开始到开始”的间隔执行；上一张未结束时不并发堆积。失败任务没有无限重试；需要用户重试或等待下一次采集。

浏览器相机离开人员页、网页隐藏或关闭相机时会释放取景。机器人模式未来由设备主动轮询，网页关闭后仍可按已保存配置采集，但当前固件还没有这段驱动。

## 三个独立入口

| 来源 | 使用方法 / 对外接口 | 登录方式 | 当前情况 |
| --- | --- | --- | --- |
| 自己上传照片 | 页面“①手动上传”；POST `/api/camera/upload`，multipart 字段 `image` | 网页 session | 实际上传、陌生人框、登记姓名均已验证 |
| 单片机相机 | “②单片机相机”；POST `/api/camera/device/poll` 领取任务，再 POST `/api/camera/device/upload` 传 JPEG/PNG | Bearer + 单次任务票据 | 网页协议和真实图片处理已验证；板端驱动尚未实现 |
| 电脑摄像头 | “③电脑摄像头”；选择摄像头、打开并允许权限，启用定时拍照并保存 | 网页 session；capture 租约 + upload | 虚拟摄像头验证；USB 实物待验收 |

三个入口共用检测/比对、人脸框、历史记录、保留策略。手动上传不需要打开摄像头，电脑没有摄像头也能用前两个入口。USB 摄像头接入后点击“查找摄像头”，可选设备；没有设备或权限拒绝有明确提示。

电脑画面来自访问网页的那台电脑，不是 Flask 服务器上的摄像头。这里的“本地识别”指 **Flask 服务所在机器**：局域网模式在运行网页的电脑识别，部署到云端则在云服务器 CPU 上识别。它不调用外部通用视觉 API，也不是在 F407/ESP 上跑模型。不做舵机跟踪或活体检测。

## 中心偏差、角度与单目标输出（06新增）

“目标中心偏差与角度”面板显示每张人脸的中心、像素偏差与水平/垂直角度。图中白十字表示画面中心，黄色点与黄色框表示选中的目标。只在 **已经通过人脸匹配阈值及候选分差** 的人脸中选择相似度最高的一张；同分保留检测顺序。未知人脸仍显示框、偏差、角度，但不成为已匹配目标；无人或失配时 `target=null`，不会沿用上一张图片的目标。

- `frame_size`：保存图片的宽/高，例如1280×960。它可能已经过上传缩小，不是用户原始大图或模型640长边坐标。
- `center_px`：人脸中心在保存图片内的x/y像素位置。
- `offset_px`：中心减画面中心，**右为正、下为正**；`offset_normalized` 是偏差除以半幅宽/高（中间0，边缘±1）。原引擎 `center`/`bbox` 保留模型 `size` 坐标，使用新字段时不要混用。
- `angles_deg.yaw`：水平相对修正角，**右为正**；`angles_deg.pitch`：垂直相对修正角，**上为正**，角度单位为度。
- 在“采集与分析设置 → 中心偏差与角度换算”设 `horizontal_fov_deg` / `vertical_fov_deg`，支持1~175度。默认60°/45°仅参考，需用相机实际完整视场角校准；数字变焦/裁剪/相机切换后需重新核对。保存后重新检测旧图片才会更新角度；每条结果保留其所用FOV。

使用针孔模型，假定主点在图像中心、不校正镜头畸变。设归一化偏差为nx/ny，射线为 `(nx*tan(HFOV/2), -ny*tan(VFOV/2), 1)`；yaw=atan2(ray_x,1)，pitch=atan2(ray_y,sqrt(1+ray_x²))，弧度转为度。因此不是简单把像素百分比乘角度。视场角不准会影响角度；单张来源照片如果不是对应相机的完整视野，角度仅供演示。

这些值是让相机对准人脸的 **相对视线角度**，不能直接当作舵机绝对PWM角度。后续控制需加当前姿态、轴向映射、机械限位及安装偏移；当前不自动发送硬件动作。

GET `/api/camera/status` 的每条记录 `analysis` 返回 `faces`（每脸偏差/角度）、单个 `target`、`target_policy`、`target_reason`、`frame_size`、`angle_config`；网页会显示这些值，也可以复制目标JSON或导出完整记录。鉴权保持网页登录session，不扩大设备Bearer授权范围。例：在1280×960图中人脸中心为960,480，FOV为60°/45°时，offset_px=[320,0]、yaw≈+16.102°、pitch=0°。

## 人员数据的处理与保留

- 配置、任务记录和 JPEG 放在服务目录 `camera_data/`，不混入旧红外人员统计、聊天历史或音频记录。
- 上传立即返回 HTTP 202；分析在后台进行。状态包括 capturing / stored / analyzing / done / failed / expired / cancelled。前端显示真实状态和失败原因，不生成模拟人员结论。
- 分析返回 `engine`、`face_count`、`faces`、`boxes`、`size`、`elapsed_ms`、`summary`。`boxes` 是相对图片宽高的归一化 x/y/w/h，含姓名、是否匹配、相似度；原像素坐标对应引擎返回的 `size`。这是人脸检测与已登记参考库比对，不是全身人体框、实名认证或活体检测。脸太小、背面或遮挡可能不出框；未检测到脸不等于画面无人。
- 每设备默认保留 50 条，可设 5~500 条；超限清理最早的已结束记录及对应图片，进行中的任务不会被清理。页面显示/导出最近 50 条记录 JSON；JSON 不嵌入原图，图片另行下载。
- 两个分析任务为全服务接纳上限，原引擎锁内串行推理；满时返回 429。一个设备已有采集/分析时会暂缓下一次拍照。重启服务后，未完成任务标记为失败，需要手动重试。
- 暂停只停止新采集；已接收的本地分析会结束。手动上传是独立测试入口，不受定时拍照时段/开关限制，但仍受上传大小和分析并发限制。
- 图片查看/下载、配置、删除、重试、皮肤清单均需网页登录。图片无公共静态地址。
- 人脸库保存在 `camera_data/face_library/`，含参考图和特征向量；与原独立 `vision_local` 工具的人脸库分开，不自动导入或更改旧库。删采集记录不会删已登记参考库，删人员会删其参考资料。保留原已存图片，旧记录点击重试后才更新检测结果；旧版远程视觉框不再展示。旧配置自动迁移为本地检测开启。

## 给未来 ESP/F407 的相机协议（v1）

本轮没有改 ESP/F407 固件，不向旧板下发不存在的相机命令。以下设备接口需要后续实现采集、压缩和上传。不要仅凭网页配置已保存认为实板相机已生效。

每个设备请求都加 `Authorization: Bearer <现有访问口令>`。不支持在 URL 中传口令。`device_id` 仅允许 1~64 位字母/数字/下划线/短横线，默认 esp-bridge。

1. `POST /api/camera/device/poll?device_id=esp-bridge`，JSON `{"ready":true,"protocol_version":1}`。建议每秒轮询。只有采集来源选“机器人相机”、配置启用、未暂停、时段和间隔满足时，返回 accepted=true。否则 accepted=false 并给 reason，不建立设备指令队列。
2. accepted=true 响应含 job_id、ticket、expires_in=60、upload_url。设备取得任务后才能拍照。ticket 只在领取响应中返回，不出现在历史记录里。
3. `POST /api/camera/device/upload?device_id=esp-bridge&job_id=<job_id>`，正文是裸 JPEG / PNG 二进制，另加 `Content-Type: image/jpeg` 和 `X-Capture-Ticket: <ticket>`；仍需 Bearer。当前是单张 HTTP 上传接口，未实现 MCU 串口图像分块协议或 RGB565 解码。
4. 202 表示网页已接收保存，自动本地检测在后台继续，不能等同于识别准确或硬件动作完成。相同任务重复上传、设备不匹配、过期 ticket 返回 409；坏图片返回 400，超限返回 413，分析繁忙返回 429。鉴权失败返回 401。用登录后的状态接口查询分析是否 done；设备 Bearer 只授权两个 device 接口，不授权相片下载、人脸库或管理页面。
5. 60 秒未上传则任务过期，可重新轮询；暂停/更改配置会取消尚未上传的任务。已经上传完成的任务不再接收第二张图。设备应自行限制拍照速率、处理断网及失败，不能在 MCU 相机/录音/OTA 共用资源忙时启动拍照。

服务端使用已有音频上传/设备录音状态、OTA 任务与新鲜的板端 moving 状态暂缓采集。没有遥测时不能证明板端空闲；这不是 MCU 双向互斥锁。未来固件仍需在真正启动采集前进行本地资源仲裁，录音或 OTA 后开始的情况也由板端最终处理。

浏览器侧接口：GET `/api/camera/status?device_id=...`；POST `/api/camera/settings?device_id=...` 完整配置；POST `/api/camera/capture?device_id=...` 领取浏览器拍照任务；POST `/api/camera/upload?...` multipart 字段 image，可加 job_id + X-Capture-Ticket；POST `/api/camera/jobs/<id>/retry`；DELETE `/api/camera/jobs/<id>`；GET `/api/camera/image/<id>`。浏览器接口走现有 session。

人脸库接口（网页 session）：GET `/api/camera/faces/state`；POST `/api/camera/faces/enroll`（multipart：`name`、可选 `person_id`、1~10 个 `photos`）；POST `/api/camera/faces/settings`（JSON：`threshold`、`margin`）；DELETE `/api/camera/faces/people/<id>`。采集间隔在 camera/settings 的 interval_sec 设置，和旧引擎独立工具的 interval 参数分开。

## 皮肤接口

唯一注册入口为 `static/skins/<目录>/skin.json`，原色是内置回退项。后端 GET `/api/ui/skins` 返回已通过文件校验的皮肤清单；模板使用同一清单。新增皮肤后刷新网页即可发现，不必修改页面控件逻辑。

皮肤示例：

```json
{
  "id": "nexus-red",
  "name": "NEXUS · 红黑机甲",
  "styles": "nexus.css",
  "bootstrap": "nexus.js",
  "storage_key": "companion.nexus.mode.v1",
  "default_mode": "dark",
  "model_styles": "nexus-model.css",
  "model_background": "#10151e"
}
```

styles、bootstrap、model_styles 都需是同目录本地文件名，不能是外部 URL；bootstrap 是受信任的本地外观脚本。新增皮肤可以参照 nexus.js，只负责主题偏好/外观事件，不调用设备 API。`skin-loader.js` 负责加载，`ui_skins.py` 负责清单。模型样式和背景也从配置读取，没有在训练页写死皮肤编号。登录页本次使用独立恒星样式与场景，不受控制台明暗切换影响。

原色明暗存储键 `ui_theme_v1`，红黑 `companion.nexus.mode.v1`，皮肤选择 `companion.skin.v1`。各设备/浏览器之间不自动同步。独立红黑设计源仍保留在 `网页软件/皮肤/红黑机甲`；要安装修改后的皮肤，复制到当前 static/skins 相应目录。

## 运行与更新

依赖为 Pillow（图片解码/去元数据）、OpenCV 4.14 与 NumPy 2，详见 requirements.txt。完整包已经附带现有 YuNet/SFace 两个 ONNX 模型、来源校验和许可证，约 39 MB；不需要另行下载模型。原独立工具引擎与模型未修改，网页中的引擎副本与原文件 SHA256 相同，见 face_local/来源说明.md。

局域网启动/云端部署脚本已纳入依赖检查、新增后端文件和 face_local 目录，并实际初始化模型预检。首次本机启动可能需要联网安装 Python 依赖（安装后识别不联网），使用独立 .venv_lan。升级保留 config.json、音频、数据库和 camera_data。修改模板/后端后需要重启网页服务；只刷新旧服务不会加载全部变化。当前没有代替用户部署云端、重启已有服务或烧录固件。

验收范围：真实模型测试覆盖三种上传来源、未知人员、登记/删除/重启保留、改亮度与尺寸后匹配、另一个人保持未知、多人出框，以及限流/鉴权/时段；浏览器覆盖画框、登记、虚拟摄像头和五种宽度两套皮肤。未测试实物 USB 摄像头、真实单片机图像采集、复杂场景准确率及云服务器性能。

服务按现有单进程、多个请求线程运行；本模块分析配额/设备握手状态在该进程内。不要改成多个 worker 共用同一 camera_data，否则需要额外的跨进程租约和全局分析队列设计。

## 1. 这是什么

**INMP441** —— 数字输出的 MEMS 麦克风模块，6 个脚。
它内部就已经是「麦克风 + 24 位 ADC + I2S 接口」了，**出来的是数字音频，不是模拟电压**。

和常见的另一种麦（MAX4466 / MAX9814 那类）的区别，决定了你要用哪套代码：

| | INMP441（本模块） | MAX4466/MAX9814 |
|---|---|---|
| 输出 | **数字**（I2S 三线） | 模拟电压（一根线） |
| STM32 这边 | I2S 外设 + DMA | ADC + 定时器采样 |
| 抗干扰 | 好（数字信号） | 差（模拟走线容易吃噪声） |
| 代码 | 本目录的驱动 | 完全不同，得另写 |

> ✅ **已确认（2026-09-18，用户报实物脚名）**：模块上的 6 个脚是
> **`SCK` / `WS` / `L/R` / `SD` / `VDD` / `GND`** ⇒ 有 3 根信号线（SCK/WS/SD）
> ⇒ **就是 INMP441 这一类数字麦，本驱动适用**。
> （对照：模拟麦只有 1 根信号线 `OUT`/`AN`，那套代码完全不同。）

## 2. ★ 接线表（引脚位置）

| 本块实物位置 | 模块脚 | 接到 STM32 | 是什么 | 必需? |
|---|---|---|---|---|
| 第 1 根 | **SCK** | **PB10** | I2S2_CK（位时钟，STM32 出） | ✅ |
| 第 2 根 | **WS**  | **PB9**  | I2S2_WS（声道选择，STM32 出） | ✅ |
| 第 3 根 | **L/R** | **GND**  | 选声道：接地 = 只驱动**左**声道 | 🟡 接 GND 最省事；不接会乱 |

> 换一块模块/换一批货 ⇒ **顺序可能完全不同，必须重新按丝印对名字**。

**就这 6 根。** 没有别的脚。

> 手上这块实物（**2026-09-18 用户确认**）从左到右是：
> **`SCK` / `WS` / `L/R` / `SD` / `VDD` / `GND`**。
> 所以下面的图**按这个实物顺序**画；接线时**逐根对名字**，别看"第几根"。

> ⚠️ **VDD 只能 3.3V。** INMP441 的绝对最大供电是 3.6V，**接 5V 直接烧**。
> 它和本板安全线要分开看：J1 第 28 针那根 5V 是给屏的，**不要拿来喂麦克风**。

> ⚠️ **SD 那根线是关键**：它从麦流向 STM32。接错/没接，现象是"音量一直是 0"，

## 3. ★★ 为什么偏偏是 PB9 / PB10 / PC3

这不是随便挑的，是被**其他模块挤出来**的结果。三件事按顺序决定了它：

### ① 为什么不用 I2S2 的"主用脚"PB12/PB13/PB15

PB12/PB13/PB14/PB15 + PC5 是**板上屏的触摸 SPI**（TCS/TSCK/MISO/MOSI/IRQ）。
触摸驱动虽然还没写，但那是**屏占着的物理脚**，抢了以后触摸功能就没法做了。
详见 `引脚分配表.md` §5。

### ② 为什么 PB10 躲不掉 —— 本模块**唯一**的代价

I2S2 的位时钟 `I2S2_CK` **只有两个可能**：`PB13` 或 `PB10`。
PB13 归触摸 ⇒ **只剩 PB10**。

⇒ **PB10 一给麦克风，USART3 就废了**（USART3_TX = PB10）。
而 `Hardware\14ESP_UART` 用的正是 **USART3（PB10/PB11）**
⇒ **"麦克风"和"ESP 走 USART3"是二选一。**

> 🟢 **现阶段没有实际损失**：`esp_uart.c` 虽然登记在工程里，但
> **`main.c` 根本没 include 它、也从没调过 `ESP_UART_Init()`**
> （ESP 实际走的是 USART1 / PA9-PA10）。
> ⚠️ 但**别同时**去调 `ESP_UART_Init()` —— 两边都不报错，只是麦克风没声。

### ③ 为什么不用 I2S3（PA15/PB3/PB4）

`I2S3_CK` 只能是 **PB3 或 PC10**：

- PB3 = 板载 **W25Q16 的 SPI1_SCK**
- PC10 = **SDIO_D2**（SD 卡数据线）

两条路都被占死 ⇒ **I2S3 在本板上用不了**。（顺带说明：这也解决了地图里
"JTAG 到底关没关"的悬念 —— 那个问题只在用 PA15/PB3/PB4 时才存在，
本驱动不碰它们，所以无关。）

## 4. 用法

### 4.1 API

```c
#include "inmp441.h"

g_mic_ok = (INMP441_Init() == 0u) ? 1u : 0u;   /* ⚠️ 必须在 UART_Init() 之后调（内部会 printf） */
if (g_mic_ok)
{
    INMP441_Start();                 /* 开始采集 */
    (void)INMP441_Calibrate();       /* 定标左声道在缓冲里的奇偶位置（约 50ms） */
    INMP441_Diag();                  /* 自检：把时钟链和数据线实况打出来 */
}
```

| 函数 | 作用 | 备注 |
|---|---|---|
| `INMP441_Init()` | 配时钟/引脚/DMA/中断/I2S | 返回 0 = 成功；可重复调用 |
| `INMP441_Start()` / `_Stop()` | 启停采集 | Init 后还要 Start 才进数据 |
| `INMP441_Calibrate()` | 定标左声道奇偶位置 | 返回 0 完成 / 1 等不到数据 / 2 分不出来 |
| `INMP441_Read(dst, n)` | 读**单声道**样本（已解出左声道） | 最多一次取回 512 个；返回实取个数 |
| `INMP441_Level()` | 音量 0~100（已去直流 + 开方压缩） | 都没数据时返回 0 |
| `INMP441_Rms()` / `_Mean()` / `_PeakToPeak()` | 原始统计量 | 峰峰值最适合判断"麦有没有在动" |
| `INMP441_Blocks()` | 已完成半块计数 | ★ **最有用**：没接麦时它**一直不涨** |
| `INMP441_Diag()` | 串口自检 + 诊断 | 出问题先看它打的那几行 |

参数：**16 kHz / 16 位 / 单声道**（语音识别的事实标准）。
内部环形缓冲 1024 个半字 = 64ms，双半块中断 → 主循环读"最近完成的那半块"。

### 4.2 `main.c` 里已经接好的钩子

不用你再动手，`main.c` 已经有：

- 上电时 `INMP441_Init()` + `Start()` + `Calibrate()` + `Diag()`
- 主循环里**每 500ms** 打一行音量：

```
[MIC] 音量=43% rms=812 半块=37
```

对着麦克风说话，看这个数跳不跳 —— 这就是"试试"。
嫌吵就把 `main.c` 里那段 `每 500ms 报一次麦克风音量` 的 `if` 块注释掉；
想整块关掉就把 `INMP441_Init()` 那 5 行注释掉。

### 4.3 最小示例：采一段音频

```c
static int16_t buf[512];      /* 512 个样本 = 32ms */

if (INMP441_Read(buf, 512u) > 0u)
{
    /* buf 里已经是单声道 16kHz PCM，可以直接压缩上传云端 */
}
```

## 6. 出问题怎么查

`INMP441_Diag()` 会把这几种情况**分开**报 —— 它们现象像、原因完全不同：

| Diag 打的字 | 真正的原因 | 怎么办 |
|---|---|---|
| `半块计数=0` + **`NDTR 在变`** | **中断这条路断了**（既不是接线、也不是时钟）：DMA 确实在搬数据，只是标志没被使能 / 没进 ISR | 看下一行 `DMA CR: EN=… HTIE=… TCIE=…` —— **HTIE/TCIE/TEIE 必须是 1**。是 0 就是 `DMA_ITConfig()` 被传了 LISR 的**标志掩码**而不是 CR 的**使能位**（见 `inmp441.h` 的宏说明） |
| `半块计数=0` + **`NDTR 不动`** | ① 外设压根没发 DMA 请求；**或** ② 请求发了但送不到这个流（**通道号错了**） | 看 `DMA CR: CHSEL=…` —— **`CHSEL≠0`** 就是 ②（SPI2_RX 应该走 **Channel 0**）：**`DMA_ITConfig()` 被传了标志掩码**，`CR \|= 值` 把 bit25-27 的 CHSEL 改成了 7、bit13/14 的 MSIZE 改成 32 位字，而 HTIE/TCIE/TEIE 一个都没置上 —— **2026-09-18 上机第一次就是这么挂的**。`CHSEL=0` 才是 ①，再看 `I2SCFGR: I2SE=…`：**`I2SE=0`** ⇒ 没使能 I2S；**`I2SE=1`** ⇒ 时钟没进外设，回去查 PLLI2S 那行的 `I2SDIV` |
| `两个槽都恒定` | SD 数据线没在动（**这时 DMA 正常在搬**，所以不是时钟问题） | 查 PC3 有没有接好、麦有没有供上 **3.3V**、SCK/WS 有没有接反 |
| `被判定为左声道的那个槽是恒定的` | **L/R 判定反了** | 把 `inmp441.h` 里的 `MIC_LEFT_PARITY` 取反（0↔1） |
| `数据正常` 但音量一直 0 | 麦在响但太小 / 供电压根没上 | 检查 VDD 是不是真的 3.3V（万用表量一下） |

## 7. ★ I2S 原理简述

### 7.1 一句话

**I2S = Inter-IC Sound**，飞利浦定的**音频专用**同步串行总线。
长得像 SPI（都是"时钟 + 数据"），区别是它**专门为音频加了"声道"概念**，
并且把"谁是时钟源"这件事写死在协议里。

### 7.2 四根线，各管什么

| 线 | 全名 | 管什么 | 本例的值 |
|---|---|---|---|
| **SCK**（CK/BCLK） | 位时钟 | **每来一个脉冲传 1 位** | 16000 × 2 × 16 = **512 kHz** |
| **WS**（LRCK/FS） | 声道选择 | **它才是"采样率"**。一个完整周期 = 一帧 = 左右各 16 位 | **16 kHz** |
| **SD** | 串行数据 | 音频数据本身，二进制补码，**MSB 先出** | — |
| **MCLK** | 主时钟 | 给编解码器用的"母时钟"（256 × 采样率） | **不用**（INMP441 自己产生） |

⚠️ **最容易搞混的一点**：采样率是 **WS 的频率**，不是 SCK 的。
SCK 比 WS 快 32 倍（16 位 × 2 声道）。

**WS 高 = 右声道，WS 低 = 左声道** —— 这是 I2S 标准的约定。
INMP441 的 L/R 脚就是告诉它"你负责哪个声道"；接 GND 就是"我只管左声道"，
另一个声道时序里它把 SD 脚**置成高阻**（所以 STM32 那边会读到恒定的值）。

### 7.3 主 / 从：为什么 STM32 必须当主机

I2S **没有"请求-应答"**，谁也别说"我要发数据了"。时钟一停，数据就停。
所以两边必须事先约好**同一个时钟源**，否则采样率对不上、音调就跑（快放/慢放）。

- **主机（Master）**：出 SCK 和 WS（有时也出 MCLK）。本项目是 **STM32 当主机**。
- **从机（Slave）**：只管按收到的时钟往外吐/往里收。INMP441 是从机。

### 7.4 "晚 1 个 SCK"—— I2S 和普通 SPI 最不一样的地方

WS 翻转之后，数据**不是立刻**变，而是**等 1 个 SCK 才出第一位（MSB）**。

留这 1 拍是给从机留反应时间。也正因为这 1 拍，**WS 的边沿本身不能当数据用**。

⇒ 这就是配置里那个 `I2S_Standard_Phillips` **不能改**的原因。
改成 `I2S_Standard_MSB` / `LSB` 会**整帧错位**，现象不是报错，是**一片噪声**。

### 7.5 时钟从哪来 —— F4 上最坑的一处

**I2S2 的时钟不是 PCLK1，而是一个独立的 PLL：`PLLI2S`。**

而且 —— **库函数 `I2S_Init()` 是直接去读 `RCC->PLLI2SCFGR` 和 `PLLCFGR`
自己反算分频的**，不是你把采样率告诉它、它去算。

⇒ 所以**必须先配 PLLI2S、再调 `I2S_Init()`**。
顺序反了它按旧值算，采样率跑到几十 kHz（现象："声音又尖又快"），**一句警告都没有**。

本项目的实际数字：

```
HSE 8MHz  ÷ PLL_M(8)  = 1MHz        ← PLLI2S 的输入
1MHz × 258 ÷ 3        = 86MHz       ← I2S 的时钟（RCC_PLLI2SConfig(258, 3)）
86MHz ÷ (168 × 32)    = 15997 Hz    ← 实际帧率（标称 16000，误差 −0.02%，听不出来）
                          ↑ I2SDIV=84, ODD=0 由 I2S_Init() 反算得出
```

> ⚠️ 还有一个**静默失败**：如果 `I2SDIV` 反算结果越界（不在 2~255），
> 库会**悄悄回落到 `I2SDIV=2`**。所以 `INMP441_Diag()` 特意把
> **实际寄存器值**打出来，而不是把配置宏再念一遍。

### 7.6 24 位的麦，为什么只取 16 位

INMP441 是 24 位器件，但本驱动配的是 **16 位帧**（一帧 = 左 16 + 右 16）。
数据 MSB 先出 ⇒ 被读走的正好是**最高的 16 位**，丢的是最低 8 位的精度。

为什么够了：人声的有效动态约 60 dB，16 位有 96 dB。
要拿全 24 位得把 `I2S_DataFormat` 改成 24b/32b，**但那样 DMA 每次要读两下
数据寄存器才凑得齐一个样本**，麻烦且对"上传云端做语音识别"没有任何收益。

### 7.7 为什么代码里要"隔一个取一个"

因为 DMA 收到的是**左右交错**的流：`左,右,左,右,…`
而 L/R 接地 ⇒ 只有左槽是真数据，右槽是高阻（恒定值）。

⇒ 必须按奇偶挑一路，否则**一半样本是垃圾**，音量/波形全是错的。

至于是"偶数下标是左"还是"奇数是左"，取决于 I2S 使能时从哪个声道开始 ——
所以有了 `INMP441_Calibrate()`：**它靠"哪个槽在变化"自动判定**
（真数据会抖，高阻槽恒定），判完写进内部状态。
判错了 Diag 会专门报一行让你把 `MIC_LEFT_PARITY` 取反。

## 8. 坑清单（都踩过或已在代码里防住）

| 坑 | 后果 | 防在哪 |
|---|---|---|
| **把 `DMA_IT_HTIF3` 这类"标志掩码"传给了 `DMA_ITConfig()`** | `DMA_ITConfig` 只是 `CR \|= 值`，于是标志掩码压到了别的字段上：**`CHSEL` 被改成 7**（SPI2_RX 的请求再也送不到这个流 ⇒ **DMA 一个字节都不搬**）、`MSIZE` 从半字变成 32 位字，而真正想要的 `HTIE`/`TCIE`/`TEIE` **一个都没置上** ⇒ `半块计数` 恒 0、`NDTR` 也不动，**看起来和"I2S 没跑 / 线没接"一模一样**（2026-09-18 上机第一次就这么挂的） | `inmp441.h` 把两套宏分开命名：`MIC_DMA_IT_EN`（SxCR 使能位，给 `DMA_ITConfig`）↔ `MIC_DMA_IT_HT/TC/TE`（LISR 标志掩码，给 `DMA_GetITStatus`/`ClearITPendingBit`）；`Diag()` 会打印 `CHSEL`/`MSIZE`/`HTIE`/`TCIE`，一眼可辨 |

| 顺序反了：先 `I2S_Init()` 再配 PLLI2S | 采样率跑到几十 kHz，**无声报错** | `inmp441.c` ①→⑧ 编号注释 |

| 忘了把 `stm32f4xx_spi.c` 登记回工程 | `I2S_Init` 链接失败（Round B 瘦身时把它砍了） | 已补登记进 LIB 组 |
| L/R 不接 | 声道判定乱、音量恒定 | 接 GND；Diag 会报"判定反了" |
| VDD 接 5V | **烧模块** | 接线表里标红了 |

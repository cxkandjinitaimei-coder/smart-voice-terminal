# 代码注释规范

本仓库的注释用于帮助下一位维护者理解硬件边界、协议约束和故障处理顺序。注释以中文为主，代码、库名、协议字段、日志字段和芯片厂商原文保留英文。

## 文件头必须回答的问题

主链路源文件开头应说明：

1. 当前文件负责什么，以及明确不负责什么；
2. 谁调用它、它调用哪些模块；
3. 输入、输出、串口帧或 HTTP 格式；
4. 资源限制，例如 RAM、Flash、DMA 环、队列长度和阻塞时间；
5. 调试方法、互斥条件和已知限制。

文件头不写聊天记录、不写真实密码、Token、照片路径或本机绝对路径。第三方库、生成数组、授权文本不机械改写。

## 状态机注释顺序

涉及协议或时序的代码，按实际执行顺序标出：

```c
/* 阶段一：判断起始/同步头，错误字节只丢弃并继续找下一帧。 */
/* 阶段二：读取固定头和长度，先做上限检查，禁止越界写入。 */
/* 阶段三：接收数据，期间只更新状态，不调用慢速显示或文件操作。 */
/* 阶段四：校验长度、序号和 CRC/XOR，失败整帧作废并重新对齐。 */
/* 阶段五：提交结果；只有提交成功后才推进序号或释放缓存。 */
```

这样写是为了说明“为什么不能把某段代码挪到别处”，而不是逐行翻译语句。互斥、超时、重试、回执和断电恢复必须写出边界条件。

## 网关和服务端

网关注释要区分 Wi-Fi 维护、UDP 发现、UART 收帧、HTTP 取队列、发送回执和 OTA/录音互斥。服务端注释要区分入队、领取、下发、回执、超时和重启后的非持久状态，不能把“已入队”写成“设备已执行”。

## 维护要求

新文件沿用本规范；改协议时同时更新发送端、接收端和回归测试。注释描述的上限必须与常量一致，若硬件实测改变，先改协议说明再改实现。

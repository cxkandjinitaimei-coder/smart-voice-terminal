# ESP8266环境搭建

适用工程：`firmware/ESP_Gateway/ESP_Gateway.ino`。目标是**NodeMCU ESP8266、4MB Flash**，不是ESP32-S3。Arduino草图目录与主`.ino`必须同名，外层项目目录可更名。

## 一、开发依赖

| 软件/库 | 版本或要求 | 用途/获取方式 |
| --- | --- | --- |
| Arduino IDE | 2.x可作为图形入口 | 官网<https://www.arduino.cc/en/software> |
| Arduino CLI | 可选，与IDE任选一种操作方式 | 命令行管理开发板包、编译、上传 |
| ESP8266 Core | **3.1.2** | 开发板管理器安装，包含编译工具链和内置库 |
| ArduinoJson | **7.4.3** | 库管理器安装，用于JSON解析/构造 |
| USB串口驱动 | 按NodeMCU实际桥接芯片选择 | 常见CH340或CP210x；系统已识别串口则无需重复安装 |

`ESP8266WiFi`、`WiFiUdp`、`LittleFS`、`ArduinoOTA`、`ESP8266httpUpdate`、`ESP8266WebServer`随ESP8266 Core提供，不要再安装同名第三方替代库。`bridge_*.h`是本项目源码，不是需要到库管理器寻找的依赖。

## 二、Arduino IDE安装开发板包

1. 安装并打开Arduino IDE，在“首选项”的“附加开发板管理器网址”加入：

   ```text
   https://arduino.esp8266.com/stable/package_esp8266com_index.json
   ```

2. 打开开发板管理器，搜索`esp8266`，安装ESP8266 Community的**3.1.2**。
3. 打开库管理器，搜索`ArduinoJson`，安装**7.4.3**。
4. 选择开发板`NodeMCU 1.0 (ESP-12E Module)`，Flash配置为**4MB，文件系统2MB**。命令行对应的关键选项是`eesz=4M2M`；IDE具体菜单文字随版本略有不同。
5. 暂时保留其余开发板默认参数，接入USB后选择实际COM端口。

若找不到端口，先检查数据线是否支持数据、设备管理器是否识别串口桥芯片，再安装对应厂商驱动。库安装失败和板卡驱动未识别是两种不同问题。

## 三、填写私有配置

先按[网页环境说明](网页服务环境搭建.md)生成服务端`config.json`。在项目根目录执行：

```powershell
Copy-Item firmware/ESP_Gateway/gateway_config.example.h firmware/ESP_Gateway/gateway_config.h
```

**仅首次缺少本地配置时复制**；已经填写过时直接编辑现有文件，避免覆盖。关键宏：

| 宏 | 需要填写的内容 |
| --- | --- |
| `GATEWAY_WIFI_SSID` | 2.4GHz Wi-Fi名称 |
| `GATEWAY_WIFI_PASSWORD` | 对应Wi-Fi密码 |
| `GATEWAY_SERVER_HOST` | 网页电脑/服务器的可达IP或主机名，仅写主机，不加`http://`和路径 |
| `GATEWAY_SERVER_PORT` | 默认5000，与服务端port一致 |
| `GATEWAY_API_TOKEN` | 从私有`config.json`复制的token，不是AI提供商的API Key |
| `GATEWAY_DEVICE_ID` | 稳定设备ID，默认`esp-bridge`，网页选择相同设备 |
| `GATEWAY_OTA_HOSTNAME` | ESP自身ArduinoOTA的局域网名称，默认`esp-gateway` |

SSID、密码和token是C字符串，包含双引号或反斜杠时需转义。ESP8266不连接5GHz专用网络。服务器候选IP不能填127.0.0.1；局域网发现优先，但端口仍使用编译配置值。该文件已被Git忽略，不要将真实信息填回公开example模板。

## 四、IDE编译与首次USB上传

1. 打开`firmware/ESP_Gateway/ESP_Gateway.ino`，保持同目录所有实现头齐全。
2. 先点击“验证”，确认选择的是ESP8266 Core 3.1.2和正确开发板。
3. 准备首次写入时，选择实际串口并点击“上传”。USB首次写入是ESP自己的固件，不会替F407安装Bootloader。
4. 完成后按下述方式观察日志，再接入F407链路。

上传时USB串口和F407都可能驱动ESP的GPIO3/RX，应避免两路发送端同时接入。必要时先断开板间UART接线完成USB上传，再恢复接线；不要在板间协议串口上用串口助手持续发送文本。

LittleFS用于音频/图片暂存和参数缓存，固件自行挂载和创建文件；当前不需要给ESP单独上传网页或SD表情文件。选择错误的Flash/文件系统分区会影响缓存和OTA空间，不能因能启动就忽略该项。

现有ArduinoJson兼容接口可能出现弃用警告；它与编译失败不是同一回事。本次公开版本没有为消除警告而改动业务接口，实际验证边界见[验证记录](validation.md)。

## 五、可选：Arduino CLI方式

安装CLI并确保`arduino-cli version`能运行。在项目根目录执行：

```powershell
arduino-cli core update-index --additional-urls "https://arduino.esp8266.com/stable/package_esp8266com_index.json"
arduino-cli core install esp8266:esp8266@3.1.2 --additional-urls "https://arduino.esp8266.com/stable/package_esp8266com_index.json"
arduino-cli lib install "ArduinoJson@7.4.3"
arduino-cli core list
arduino-cli lib list
arduino-cli board list
arduino-cli compile --fqbn "esp8266:esp8266:nodemcuv2:eesz=4M2M" --output-dir ".build/esp" firmware/ESP_Gateway
```

如需实际上传，将`COM5`改为本机ESP端口：

```powershell
arduino-cli upload -p COM5 --fqbn "esp8266:esp8266:nodemcuv2:eesz=4M2M" --input-dir ".build/esp" firmware/ESP_Gateway
```

编译和上传分开执行；`--input-dir`明确使用刚导出的产物。Linux/macOS用相应串口设备名；它们的CLI命令形式相同，但本项目固件实编证据来自Windows。若IDE和CLI使用不同数据目录，应分别核对已安装的Core和库，不能假定共享配置。

## 六、板间接线与日志口

| ESP端 | F407/调试设备 | 参数 |
| --- | --- | --- |
| GPIO1/TX（UART0） | F407 PC7/RX | 921600、8N1 |
| GPIO3/RX（UART0） | F407 PC6/TX | 921600、8N1 |
| GND | F407 GND | 共地，逻辑3.3V |
| GPIO2/D4（Serial1 TX） | 独立USB-TTL的RX | 115200，仅日志输出 |

F407自己的日志在PA2/TX、PA3/RX，115200；这与板间USART6是两路串口。NodeMCU USB连接UART0，运行时承载板间协议，**不能把这里收到的二进制内容误认为调试日志乱码**。GPIO2是启动相关引脚，日志接收端不得在上电时强拉低；供电方式按NodeMCU开发板原理图确认。

初次验证建议先启动服务器，再上电ESP与F407。日志应能看到固件版本、Wi-Fi、服务发现或候选地址连接；网页设备最近在线时间应持续更新。仅显示Wi-Fi已连接，不代表服务已鉴权、F407已响应或传感器已有数据。

## 七、OTA与常见问题

ESP自身ArduinoOTA和F407升级转发是两条不同路径。当前F407局域网直传接口在ESP的TCP8080；设备主动向服务端拉取的流程则使用服务器HTTP端口。ESP自身ArduinoOTA使用本地网络发现和相应OTA通信，首次搭建不必先打通它，USB上传即可验证网关。

| 现象 | 检查 |
| --- | --- |
| 提示复制`gateway_config.example.h` | 缺少同目录`gateway_config.h`，或放错目录 |
| 找不到`ESP8266WiFi.h` | 是否选择ESP8266开发板并安装Core，而非普通Arduino/ESP32 |
| 找不到`ArduinoJson.h` | 当前IDE/CLI环境是否安装指定库 |
| Wi-Fi连上但设备离线 | HTTP端口、token、候选IP、防火墙/隔离、是否有多份旧服务 |
| F407没有收到命令 | TX/RX交叉、共地、两端921600配置，是否误用调试串口 |
| 录音缓存失败 | 4MB/2MB文件系统选项、LittleFS挂载日志及供电，不先归因于识别模型 |
| 自动升级不接受1.0.0 | 原开发版1.1.13更高，需单独安排迁移；不是改版本号字符串就能保证兼容 |

# 识别模型与工具环境搭建

先完成[网页环境搭建](网页服务环境搭建.md)的虚拟环境和requirements安装。以下命令在项目根目录执行，Windows用`.\.venv\Scripts\python.exe`，Linux替换为`.venv/bin/python`。模型和素材不属于F407片内固件。

## 一、语音识别模型

### 1. 模型、算力和目录

当前使用`Systran/faster-whisper-small`，**CPU / int8**，不要求CUDA或独立显卡。识别在网页服务所在电脑/服务器运行；ESP只搬运PCM，F407采样并做VAD触发/断句。

首次下载约数百MB，应为缓存、Python依赖和录音保留额外空间。CPU核数、内存、句子长度和并发影响延迟，项目未给所有机器制定实测最低配置。默认缓存为`server/Robot_Server/models/asr`，里面包含Hugging Face快照，不是任意单个`small.bin`都可替换。

### 2. 下载并验证

```powershell
.\.venv\Scripts\python.exe server/Robot_Server/download_asr_model.py
```

默认使用`https://hf-mirror.com`，串行下载、有限重试并保留可复用缓存。如需官方源，改为：

```powershell
.\.venv\Scripts\python.exe server/Robot_Server/download_asr_model.py --endpoint https://huggingface.co
```

两条任选一条，不对同一缓存同时开多个下载进程。下载进程不要被外部`HF_HUB_OFFLINE=1`强制离线；正常服务启动后只读本地模型。出现下列内容才代表本地加载、真实WAV解码和VAD验证通过：

```text
MODEL_READY: small / CPU / int8 loaded; WAV/VAD check passed.
```

`Fetching 100%`后可能仍在加载；`MODEL_NOT_READY`说明尚未完成，可保留缓存后续传。进度不动先查看大文件下载、重试或文件锁，不立即重复开启任务。

Linux远程终端需要断线继续下载，可在项目根执行：

```bash
nohup .venv/bin/python -u server/Robot_Server/download_asr_model.py > asr_download.log 2>&1 </dev/null &
tail -f asr_download.log
```

Ctrl+C只退出tail监视，不停止后台下载。再次启动下载前先查原任务和日志，成功以`MODEL_READY`为准。下载不会自动启动或重启服务。

### 3. 三层检查

```powershell
.\.venv\Scripts\python.exe server/Robot_Server/asr_check.py --app-dir server/Robot_Server --dependencies
.\.venv\Scripts\python.exe server/Robot_Server/asr_check.py --app-dir server/Robot_Server --prepare
```

| 模式 | 成功标志 | 含义 |
| --- | --- | --- |
| `--dependencies` | `ASR_DECODER_READY` | 真实WAV解码通过，不加载/下载模型 |
| `--prepare` | `ASR_PREPARED` | 本地模型加载、WAV解码和VAD通过，不启动服务 |
| `--service-url` | `ASR_READY` | 检查已启动服务中的模型状态，读取本地token完成登录 |

服务启动后在另一终端执行，端口按实际配置替换：

```powershell
.\.venv\Scripts\python.exe server/Robot_Server/asr_check.py --app-dir server/Robot_Server --service-url http://127.0.0.1:5000
```

下载后如果旧服务已记住模型加载失败，需重启再查；另一个进程的`--prepare`成功不代表旧服务已恢复。

复用外部缓存时，下载和服务必须指向同一路径，例如Windows：

```powershell
$env:ASR_MODELS_DIR = 'E:/RobotModels/asr'
.\.venv\Scripts\python.exe server/Robot_Server/download_asr_model.py --models-dir "$env:ASR_MODELS_DIR"
.\.venv\Scripts\python.exe server/Robot_Server/start_server.py
```

目录可自行修改，环境变量只影响当前终端和子进程；换终端/系统服务时也要设置。

## 二、人脸模型与人员登记

依赖requirements中的OpenCV/NumPy，权重为：

| 文件 | 用途 | 大小 |
| --- | --- | ---: |
| `face_detection_yunet_2023mar.onnx` | YuNet人脸检测/关键点 | 232589B |
| `face_recognition_sface_2021dec.onnx` | SFace特征/人员匹配 | 38696353B |

```powershell
.\.venv\Scripts\python.exe tools/download_face_models.py
```

该工具直接下载，没有`--help`入口。目标是`server/Robot_Server/face_local/models`，按`model_source.json`固定来源、大小及SHA256验证。成功输出`Downloaded and verified`或`Verified cached model`。不要用错误网页、Git LFS指针或同名其他模型替代。

下面的本地检查只加载已有模型，不拍照、不联网、不写入人员资料：

```powershell
.\.venv\Scripts\python.exe -c "import sys; from pathlib import Path; sys.path.insert(0, str(Path('server/Robot_Server').resolve())); from face_local.face_engine import FaceEngine; print(FaceEngine().public_state()['engine'])"
```

输出`YuNet + SFace / CPU`说明文件校验与引擎可初始化。实际匹配还需在网页人员/拍照相关页面登记清晰参考照，再测试另一张照片。未登记参考照时框到人脸但显示未知，并不表示模型没安装。

电脑不需要自带摄像头，可先上传图片测试；机器人拍照由OV7725经F407/ESP上传。检测置信度与身份相似度不是同一数值，像素、姿态、曝光及朝向仍影响效果。

## 三、SD表情素材

`tools/sd_assets.py`依赖Pillow，已包含在requirements。按[SD素材说明](sd-assets.md)准备片名文件夹及正确帧数。源、输出目录要彼此独立，不能相互嵌套，示例路径按实际替换：

```powershell
.\.venv\Scripts\python.exe tools/sd_assets.py "E:/RobotAssets/source" "E:/RobotAssets/export" --normal "E:/RobotAssets/normal.png" --listen "E:/RobotAssets/listen.png"
```

输出`export/FACE`，动画从0000编号，生成BMP/R16；静态图为`GUINORM.BMP`和`GUILIST.BMP`。R16是本项目160×160 RGB565格式，不是通用图片。检查后手动把FACE复制到SD根目录，工具不格式化卡、不修改驱动帧数。

只转换素材可用单独Python环境仅安装Pillow；完整业务环境复用项目`.venv`即可。

## 四、串口音频转换

`tools/dump2wav.py`用于调试十六进制dump转WAV，与网页流式上传是不同测试路径。

| 模式 | 依赖 | 示例 |
| --- | --- | --- |
| 日志文件转WAV | Python标准库 | `.\.venv\Scripts\python.exe tools/dump2wav.py "mic-log.txt" --no-play` |
| 直接串口收集调试录音 | 额外pyserial | `.\.venv\Scripts\python.exe tools/dump2wav.py COM5 --rec 2 --no-play` |

需要串口模式时再安装：

```powershell
.\.venv\Scripts\python.exe -m pip install pyserial
```

COM5替换为F407调试口，关闭占用同串口的助手。默认115200，RAM调试示例录1～2秒，不能据此认定网页10秒流式链路已通过。

## 五、版本、构建、合并和回归

| 工具 | 依赖 | 操作范围 |
| --- | --- | --- |
| `set_version.py` | Python标准库 | 同步根VERSION；`--check`只读 |
| `build_stm32.py` | Python、Windows Keil ARMCC5、fromelf | 编译导出，不烧录 |
| `merge_bootstrap.py` | 标准库及正确Boot/OTA HEX | 校验合并，不烧录 |
| `run_checks.py` | 服务requirements；可选样例/模型 | 临时目录测试，不操作硬件 |

```powershell
.\.venv\Scripts\python.exe tools/set_version.py --check
.\.venv\Scripts\python.exe tools/run_checks.py
```

真实人脸样例扩展检查需要同时提供两个参数。样例目录须含测试约定的`opencv_lena.jpg`和`opencv_messi5.jpg`等文件，不能随意指定个人相册：

```powershell
.\.venv\Scripts\python.exe tools/run_checks.py --face-assets "E:/RobotTests/public-samples" --face-models "server/Robot_Server/face_local/models"
```

未提供可选资源时，以输出跳过项为准，不能因0失败就宣称真实模型测试已运行。测试复制服务源码到临时目录并使用独立配置，不等于无线、实板和长期联合验收。构建与合并命令见[STM32环境说明](STM32环境搭建.md)。

## 六、常见问题

| 现象 | 优先检查 |
| --- | --- |
| 下载卡住/Socket超时 | 网络源、大文件进度、重试、多个任务争用缓存；先查日志 |
| 下载完仍说模型缺失 | 下载与服务目录、ASR_MODELS_DIR、账号权限，旧服务是否重启 |
| PyAV参数报错 | 当前解释器是否使用faster-whisper1.2.1及av18.1.0，重新执行解码检查 |
| 人脸模型初始化失败 | OpenCV变体混装、固定SHA256不匹配、误下载指针或错误页 |
| WAV有文件却无文字 | 先试听完整性、音量和清晰人声，VAD过滤静音属预期 |
| SD导出帧数不符 | 片名、图片数量与驱动元数据；不能只改目录名解决 |

模型、录音、人员照片/特征属于本地运行资源，不随公开源码提供。换电脑可迁移有权使用的模型缓存，Python虚拟环境应重建，不复制整个`.venv`充当安装。

# 协议与任务同步

## F407 ↔ ESP 字节流

PC6/PC7 的 USART6 为 921600、8N1。ISR 写接收环；前台解析器区分文本与二进制，不在串口中断执行 LCD、Flash 擦写或网络操作。

二进制信封：

| 字段 | 字节 | 规则 |
| --- | --- | --- |
| 同步 | 2 | `A5 5A` |
| type | 1 | 消息类型 |
| seq | 2 | 小端，当前消息的序号语义由类型定义 |
| len | 2 | 小端，payload 长度 |
| payload | len | 二进制，可含 00/CR/LF |
| XOR | 1 | type、seq 两字节、len 两字节及 payload 逐字节异或 |

先匹配帧头，再读类型/序号/长度；超长帧不得写入固定缓冲；消费声明负载后校验，成功才分派。不是所有类型共用一个业务重传节拍。`esp_uart.c` 的返回负载指向共享解析缓冲，下次解析可能覆盖，调用方必须及时处理/复制。

文本按白名单处理，例如 `@MOVE:servo,2,30,90`、`@MOVE:gesture,nod`、`@MOVE:expression,happy`、`@TEXT:你好,这里的逗号属于正文`、`@MIC:rec,10`、`@IAP:INFO`。支持的结束方式由各入口决定，常规命令尾 `#` 可选。不能把未知 ESP 文本直接交给显示兜底，否则损坏数据会意外上屏。

## 音频

- `0x01 START`：采样信息及可选 VAD 短句标记；ESP READY 后才进入发送阶段。
- `0x02 PCM`：seq 为块号，2048B=1024 个 16 位单声道样本=64ms；两份32ms DMA 半块拼成一块。
- `0x03 END`：发送/确认块数与丢半块数等收尾信息。
- `0x04 ACK`：seq 为 next_seq，flags0继续、1重传、2拒绝；窗口为1。

F407 只在 ACK 后释放发送环队尾，超时最多有限重发。DMA 完成计数不是排队样本数，漏半块不得靠重复最新音频补齐。10秒手动录制量化为156块/319488B/9.984秒。环满、丢半块、链路失败应区分上报。

服务端支持分块和裸 PCM 流接口；`audio_rx.Session` 校验会话/序号/采样参数并落盘，完整性通过后才入识别 FIFO。VAD 允许的提前结束与普通缺字节中断必须分开。HTTP ACK、ESP 上传完成、ASR 完成、AI 投递完成分别记录；不能用一个“OK”混指这些阶段。

## 参数、时间线与姿态

网页参数保存后计算修订号，ESP 反复同步到 F407，收到匹配修订 ACK 才显示已应用。单纯网页保存并不证明板端改变。机械限位依据当前固定契约；速度/动作库保留用户设置。

时间线由服务端验证和展开，一次提交给设备，设备用同一 TIM6 毫秒时基执行到期步骤。前台忙状态决定任务能否开始，不是 RTOS 锁。Python 服务的线程共享队列使用实际 `threading.Lock/RLock`，网络等待与推理尽量不长时间占用状态锁。

姿态由 F407 估计并经 ESP 回传；网页依据新鲜快照更新3D模型。它不是舵机编码器反馈。

## OTA 与局域网发现

OTA 0x10~0x1F 的具体类型/错误码由 `iap_app.h`、ESP IAP 模块和服务端共同定义，布局见 Flash 文档。设备拉取模式用于跨网络，仍保留实体确认和重启校验。

发现协议标识 `ARDP_DISCOVER` / `ARDP_IP`、默认设备 ID `esp-bridge` 属于兼容标识，不随工程目录、产品名或 AI 名称变化。自动发现仅跨同一可达局域网，不能替代公网路由。

# 环境搭建与依赖说明

适用版本：公开源码 **1.0.0**，硬件为 STM32F407VET6 + NodeMCU ESP8266 + OV7725 FIFO。本组文档供拿到源码后从零搭建，不要求保留原开发电脑的路径；下载、编译和烧录由使用者按步骤执行。

## 二、哪些部分运行在哪里

| 部分 | 运行位置 | 必要环境 |
| --- | --- | --- |
| F407应用/Bootloader | STM32F407 | Windows上用Keil/ARMCC5编译，有线工具完成首次写入 |
| ESP网关 | ESP8266 NodeMCU | Arduino IDE或CLI、ESP8266 Core、ArduinoJson |
| 网页服务与AI请求 | 电脑或Linux服务器 | Python、Flask及其他requirements依赖 |
| 语音转文字 | 运行网页服务的电脑/服务器 | faster-whisper、PyAV、本地small权重，CPU/int8 |
| 人脸检测与指定人员匹配 | 运行网页服务的电脑/服务器 | OpenCV、NumPy、YuNet/SFace权重 |
| 网页界面 | 浏览器 | 现代Edge/Chrome等浏览器；3D视图需要WebGL支持 |
| 表情素材转换 | 电脑 | Python、Pillow；生成后手动复制到SD卡 |

“云端识别”表示服务部署在远端机器；局域网部署时识别就在本地电脑运行。F407和ESP不运行Whisper或人脸模型。当前网页是Flask直接提供的HTML/CSS/JavaScript，**不需要Node.js、npm、Vue或前端打包**。Node仅可选用于开发时的JavaScript语法检查。

## 三、依赖与版本原则

| 类别 | 当前依据 | 说明 |
| --- | --- | --- |
| MCU编译器 | ARMCC 5.06 update 7，build 960 | 三个Keil工程使用的已验证编译器；未适配ARM Compiler 6 |
| 芯片支持包 | Keil.STM32F4xx_DFP 3.1.1 | 在Keil Pack Installer安装 |
| ESP开发板包 | ESP8266 Arduino Core 3.1.2 | 提供Wi-Fi、LittleFS、串口、OTA等内置库 |
| ESP外部库 | ArduinoJson 7.4.3 | 在Arduino库管理器或CLI安装 |
| Python | 项目建议3.10+、64位 | 可先选择3.11/3.12；实际依赖是否有对应安装包，以pip安装检查为准 |
| 服务运行依赖 | `server/Robot_Server/requirements.txt` | 固定和范围约束以此文件为准，见网页分项说明 |
| 模型权重 | 下载工具及`face_local/model_source.json` | 不随源码提供，不能只安装Python库就视为模型就绪 |

requirements不是包含全部间接依赖的完整锁文件。不要把旧电脑的`.venv`复制到新电脑；应重新创建虚拟环境，再安装依赖。实际构建与回归边界见[验证记录](validation.md)，下面的建议配置不等于所有系统都已实测。

## 四、推荐搭建顺序

1. 保留完整源码树，打开项目根目录终端，确认能看到`VERSION`、`firmware`、`server`、`tools`。
2. 按[网页说明](网页服务环境搭建.md)创建Python虚拟环境、安装依赖并生成`config.json`。
3. 先启动网页，确认本机能登录，再用同Wi-Fi手机访问电脑的局域网地址。
4. 下载需要的识别模型，执行依赖解码和模型准备检查；不使用识别时可先跳过模型。
5. 按[ESP说明](ESP8266环境搭建.md)填写同一token及Wi-Fi/服务器信息，编译网关固件。
6. 按[STM32说明](STM32环境搭建.md)编译Bootloader和OTA应用；新板先完成有线引导安装。已有开发板不要未经迁移确认就覆盖。
7. 按[硬件接线](hardware.md)连接，准备SD素材，观察设备上线，再分项测试温湿度、舵机、录音、拍照和OTA。

软件版本源是根`VERSION`。只更新说明文档不改版本；修改固件准备发布时按[版本与迁移](versioning.md)同步。公开ESP 1.0.0低于旧开发1.1.13，不能直接通过现有规则自动降级。

## 五、通信配置要相互对应

| 项目 | 服务端 | ESP/硬件端 |
| --- | --- | --- |
| 设备鉴权/网页登录口令 | 私有`config.json`的`token` | `gateway_config.h`的`GATEWAY_API_TOKEN` |
| HTTP服务端口 | `config.json`的`port`，默认5000 | `GATEWAY_SERVER_PORT`，必须相同 |
| HTTP服务器地址 | 本机使用127.0.0.1；其他设备用电脑实际局域网IP | 自动发现优先，`GATEWAY_SERVER_HOST`为候选地址，不能填127.0.0.1 |
| 局域网发现 | UDP5001应答 | 向UDP5001广播询问 |
| 稳定设备标识 | 网页中的目标设备与其队列 | `GATEWAY_DEVICE_ID`，不要随机器人名称修改 |
| 板间串口 | F407 USART6，PC6 TX/PC7 RX | ESP GPIO3 RX/GPIO1 TX，921600、8N1 |
| 调试串口 | F407 USART2，PA2 TX/PA3 RX，115200 | ESP另用GPIO2/D4的Serial1输出115200日志 |

服务发现当前取得IPv4地址，**不会自动替换ESP编译配置中的HTTP端口**；改服务端口时两端都要改。局域网直连F407 OTA还使用ESP的TCP8080；ESP自身ArduinoOTA是另一条更新路径，不能把它们混为同一个端口。

## 六、完成后的逐项判断

| 检查 | 正常表现 |
| --- | --- |
| Python依赖 | `pip check`不报告依赖冲突，能导入Flask、cv2、faster_whisper和av |
| 本机网页 | 能打开`http://127.0.0.1:5000/`并用本地token登录 |
| 局域网访问 | 同网段手机能访问电脑IP对应网页；仅本机能开不代表ESP能连 |
| ESP连接 | 串口显示联网及服务地址，网页设备最近在线时间持续更新 |
| F407启动 | 调试输出到主循环，OTA应用报告正确Slot A地址，屏幕可切页 |
| 传感器 | 温湿度值和时间戳变化；页面有配置项不等于采样上传成功 |
| 音频 | 上传完整、历史记录可试听，识别模型就绪后产生文本；静音可能正确返回无人声 |
| 相机 | 请求得到完整图片，加载模型后才检查检测/匹配；有图片不等于已识别 |
| OTA | 实体确认后传输，安装复位并回传版本/校验结果，网页最终完成 |

本组文档不包含个人Wi-Fi/API密钥、人物照片、录音或模型权重，也不会自动安装、烧录、部署或删除现有文件。需要排障时按各分项文档中的“现象—检查”定位。
